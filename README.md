# 일본어 문장 노트 — 운영 메모

매일 문장을 추가할 때 Claude가 먼저 읽는 파일. 여기 적힌 규칙대로 `data.js`에 항목을 추가한다.

## 학습 목표

- **주 목적: 일본인과 실제로 대화하기.** 시험이 아니라 말하기가 목표.
- 계기: 게스트하우스에서 일본인과 대화할 기회가 있었는데 한마디도 못 했다. 다음에는 입이 열리도록 한다.
- 그래서 모든 예문은 **여행지·게스트하우스·식당·길거리에서 바로 꺼내 쓸 수 있는 말**로만 든다. 교과서식 예문(비가 와서 안 갑니다 등)은 쓰지 않는다.
- 우선 상황: 자기소개, 여행 이유 말하기, 상대에게 질문하기(어디서 왔어요? 추천 있어요?), 주문, 길 묻기, 못 알아들었을 때 되묻기, 감사·사과.

## 학습자 수준

- 히라가나 절반 정도만 읽을 수 있음. 가타카나·한자는 거의 모름.
- 따라서 **일본어가 나오는 모든 곳에 히라가나 + 한글 발음 + 한국어 뜻**을 빠짐없이 붙인다. 하나라도 빠지면 읽을 수 없다.
- 말투는 따로 요청이 없으면 정중체(です・ます). 게스트하우스에서 처음 만난 사람에게 쓰기에 알맞다.

## 학습 페이스: 카드 1개 = 3일

카드 하나(문장 7개, 문법 3개)는 하루 분량으로 너무 많다고 사용자가 판단함. **3일에 카드 1개**, 매일 조금씩.

- 1일차 · 문장: 메인 문장과 단어만. 한글 줄 보고 소리 내어 10번 → 히라가나 줄로 읽기. 안 보고 말하기가 목표.
- 2일차 · 문법: 문법 3개와 예문 소리 내어 읽기. 어제 문장 복습.
- 3일차 · 바꿔 말하기: 비슷한 표현·변형 2개 읽고, 자기 상황으로 한 문장 만들어 보기. 이 문장이 다음 카드 재료가 될 수 있음.

→ 새 카드는 **3일마다** 추가. 사용자가 중간에 요청하면 그때 추가. 카드마다 "진도" 체크(1·2·3일차)가 있음.

## 하루 작업 흐름

1. 사용자가 **문장을 직접 주거나**, "**이런 말을 하고 싶다**"는 상황만 준다.
2. 상황만 준 경우 문장을 만든다. 카드당 메인 문장 1개. 새 문법은 카드당 3개 이내.
3. 기존 `data.js`를 훑어서 이미 나온 단어·문법을 재활용한다. 새 문장이 이전 문장과 연결되게 한다.
4. `data.js`의 `window.SENTENCES` 배열 **맨 아래**에 항목을 추가한다. 화면(`index.html`)은 건드리지 않는다.
5. `node -e "global.window={};require('./data.js')"`로 문법 오류를 확인하고 `open index.html`로 열어 준다.
6. `python3 tools/make_audio.py`로 음성 생성 (VOICEVOX 자동 실행·종료).
7. 사용자에게 추가한 문장을 간단히 요약해 보여 준다.

## 항목 작성 규칙 (`data.js`)

형식은 `data.js` 맨 위 주석 참고. 반드시 지킬 것:

- `id`: `YYYY-MM-DD-n` (같은 날 두 번째 문장은 `-2`). 중복 금지 — 복습 체크 저장 키로 쓰임.
- `tokens`: 구두점 제외 **모든 토큰에** `r`(히라가나), `k`(한글 발음), `m`(뜻), `pos` 채움. 한자가 있으면 `f`로 후리가나 위치 지정.
- `pos`는 한국어로만 쓴다. 예: "동사 ‘가다’ + 희망", "조사". 일본어 구성 설명은 `note`에 마크업으로.
- `grammar`: 각 항목에 `title`, `r`, `k`, `m` + 아래 네 칸을 **섞지 말고 따로** 채운다 (한 문단에 뒤섞으면 읽기 어렵다고 사용자가 지적).
  - `form`: 만드는 공식 한 줄. 예: `"동사 ます형 어간 + {{たい|たい|타이|~하고 싶다}}"`
  - `steps`: 공식을 실제 단어에 적용하는 과정, 한 단계 한 줄 (배열, 2~3개). 마지막은 완성형.
  - `note`: 어감·쓰는 상황, 짧은 문장 1~2개 (배열). 공식 설명을 여기 넣지 않는다.
  - `ex`: 여행에서 쓸 예문 1개 (`ja/r/k/m`). 뜻에 쓰는 상황을 괄호로. 예: "(메뉴를 가리키며)".
- `similar`: 같은 뜻의 다른 표현 1개(`ja/r/k/m/note`) + `more`에 **단어만 바꾼 예문 2개**(`ja/r/k/m/diff`). 모두 여행·일상용.
- 예문(`ex`, `similar`, `more`)의 `ja`/`r`는 **단어 사이를 띄어쓰기로 끊어** 적는다(구조 파악용). 화면에서 " / "로 보인다. 구두점은 앞 단어에 붙인다. 예: `"これ を 食べたい です。"`
- 예문의 `k`(한글 발음)는 **끊어 읽는 덩어리를 " / "로 나눠** 적는다(말하기용). 예: `"코레오 / 타베타이데스."`
- 메인 문장은 토큰에 `b: true`를 붙여 끊어 읽는 자리를 표시한다. 화면이 한글 줄을 그 자리에서 " / "로 끊고, 조사는 앞 단어에 붙여 보여 준다.
- 끊어 읽기 원칙: 조사는 앞 단어에 붙인다. 쉼표 뒤, 조사(に·を·は·で 등) 뒤, 접속 표현(ので·から) 뒤에서 끊는다. 짧은 문장은 2~3덩어리 정도.
- 설명 글(`note`, `diff`) 안에 일본어를 쓸 때는 `{{일본어|히라가나|한글|뜻}}` 마크업. 화면에서 "일본어(한글 · 뜻)"로 펼쳐진다.
- `ko`(문장 전체 한글 발음)는 자연스럽게 이어 읽는 발음. 토큰의 `k`는 단어 단위.
- 한글 발음 표기 원칙: 장음은 모음을 덧붙여 표시(べんきょう → 벤쿄오), を는 "오", 어말 ん은 받침(ません → 마셍), っ는 앞 글자에 받침 ㅅ(ゆっくり → 윳쿠리).

## 화면(`index.html`)에서 사용자가 요청한 것들

- 깔끔하고 여백 있게. 라벨·테두리·중복 줄은 최소로. (여러 번 "덜어내 달라"고 했음)
- 단어별 분해는 **한 단어 한 줄**, 줄바꿈 안 생기게. 열: 일본어(+히라가나) / 한글 발음 / 뜻.
- 예문 박스는 일본어 / 히라가나 / 한글 발음 / 뜻 **네 줄 각각 따로**. 일본어·히라가나 줄은 단어마다, 한글 줄은 끊어 읽는 덩어리마다 " / "로 표시.
- 문법 항목은 공식 / 만들기 / 쓸 때 / 예문 네 칸으로 나눠서 표시.
- 음성: 🔊 버튼이 메인 문장과 모든 예문에 붙음. 단어 줄의 일본어를 클릭하면 그 단어만 읽음. (느리게 버튼은 부자연스러워서 사용자가 제거 요청 — 다시 넣지 말 것.)
  - **VOICEVOX**(사용자 선택, 무료·로컬)로 미리 만든 `audio/<key>.m4a`를 재생. 파일이 없으면 Mac 내장 Kyoko로 대체.
  - **카드를 추가한 뒤에는 반드시** `python3 tools/make_audio.py`를 실행해 새 m4a를 만든다. 스크립트가 VOICEVOX를 알아서 켜고(약 6초), 끝나면 끈다. 사용자에게 켜 달라고 할 필요 없음. 없는 파일만 만들어 주므로 매번 돌려도 됨.
  - 화자: **13 青山龍星(ノーマル)** — 사용자가 샘플 6개 중 선택(2026-10-19). `audio/speaker.txt`에 저장됨. 바꾸면 `--force`로 전부 재생성. 파일 이름 규칙은 `tools/make_audio.py` 상단 주석 참고 — `index.html`의 `data-key`와 맞춰야 함.
- 진도 체크(1·2·3일차), 복습 체크(1주·1달), 가리기(발음·뜻 블러), 검색, 태그 필터, 다크 모드 유지.

## 배포 (모바일에서 보기)

- GitHub 공개 저장소 `kim-jong-seong/japanese-study` → GitHub Pages.
- 주소: **https://kim-jong-seong.github.io/japanese-study/**
- 카드를 추가하고 음성을 만든 뒤 **커밋 + `git push`** 하면 1~2분 뒤 폰에서도 보인다. 푸시를 빼먹으면 폰에 안 뜬다.
- 커밋 메시지는 한국어로 짧게. 예: `카드 추가: 2026-10-22 길 묻기`

- 진도·복습 체크는 기기별(localStorage)이라 Mac과 폰이 따로 저장된다.
